# 面向 K12 的题目排版 DSL

目标是定义一门像 Markdown、LaTeX 一样可以直接用文本编写的教育领域专用语言（DSL），覆盖 K12 各学科的题目表现形式。以“一段材料供三道小题共用，第二题要求在图中标注”为例，作者需要能写清材料被哪些题引用、标注落在哪幅图上，以及换行或分页后哪些内容仍应放在一起。

v0.1 使用英文关键字，题目正文保留原语言。草案用选择题、填空题和带小题的阅读题演示两层的写法。[语法草案与完整示例](syntax-draft-v0.1.md)

## 题型层与渲染层

**题型层描述一道题展示哪些内容，以及这些内容怎样组织。渲染层描述这些内容怎样排出来。** 作答区是题面的一部分，即使只生成一张空白试卷，也需要知道它在题干中间、表格单元格内，还是整题下方。点击选项、输入答案或采集笔迹属于使用这份题面的应用交互。

| 层次 | 作者描述什么 | 可以复用什么 |
| --- | --- | --- |
| 题型层 | 题干、选项组、材料、小题与作答区的内容、顺序和归属。题干中的空位可以关联到一组备选词，小题也可以引用同一幅图。 | 选择题可组合题干和选项组，阅读题可组合共享材料与多道小题。题面上的“请选择两项”作为题干文字保留。 |
| 渲染层 | 用段落、列表、公式、图和表组织内容，为具体字词指定加粗、斜体、着重号、下划线或删除线。作者可指定必须对齐的对象，渲染器据此计算列宽、折行、分页和坐标。 | 同一个分式可出现在题干、选项或表格单元格中。同一组选项可在宽屏分列、窄屏逐行显示。 |

两层通过同一个题目对象或文字片段关联。例如，“解释加点词”在题型层把设问指向材料中的“自若”，并把释义栏标为这道小题的作答区。渲染层在这两个字下逐字加点，在释义栏画作答横线。这里“字下有点”已经写进题干，是纸面和屏显都要满足的要求；点的大小和释义栏的宽度可以随版式调整。两层引用材料中的同一处“自若”，即使文中多次出现这个词，重排后也应能定位到原处。[原卷题例与文字标记](markdown-latex-layout.md#字词上的标记怎样保留)

## 同一道完形填空里的三种关系

在英语题 Q0082 中，题型提示后有五段阅读材料，共十处空位。题库把它们对应的小题保存为 Q0083 至 Q0092，每道小题都有四个选项。Demo 根据子题顺序把每个空位关联到对应的小题 ID，再把选项交给该小题排版。[样例题库](../../demos/android/demo-geckoview/src/main/assets/gecko/catalog.json) · [题目组装](../../demos/android/demo-geckoview/src/main/kotlin/dev/techlab/android/gecko/QuestionCatalog.kt) · [空位与选项的渲染](../../docs/geckoview/render/render.js)

用这道题检验两层的边界，可以做两次独立改动。第一次只缩窄屏幕，让选项从两列排成一列，核对四个选项是否仍完整显示在原小题下方。第二次只调换小题的展示顺序，材料中第二个空位仍应指向原来的选项组。前者检验渲染能否适应宽度，后者检验题型层是否把关联误写成了显示顺序。

## 如何比较候选写法

以现有 HTML 题面为对照，给同一道题分别尝试 Markdown 扩展和独立的题目语法。两种写法都要表达相同的题型关系和渲染要求，再比较教师能否读懂和修改，以及程序能否定位到设问、作答区及其引用的内容。

v0.1 的三个例子先给出源文和预期题面。后续从样式盘点中选取原题，补齐“原题—DSL 源文—预期题面”对照与覆盖表，在窄屏和纸面宽度下核对阅读顺序、公式含义、图文对应关系与作答位置。再让另一位作者仅凭草案完成一次局部改题，例如调换共用材料下的两道小题，检查引用和作答区是否仍指向正确对象。

覆盖表逐项标明可用核心语法表达、需要学科扩展、或仍有信息丢失；缺少样例的项标为待验证。例如，整图嵌入可以保留原题外观，但图中标注点能否被单独引用，需要另行验证。根据这些具体缺口决定哪些能力应进入核心语法、哪些适合扩展。
