# 多格式文本的流式解析与预览自动闭合

当内容逐块到达时，首屏常常只收到半个标签、一段还没结束的图，或只有分子的公式。这个专题要决定，标签式 HTML、Markdown、PlantUML 时序图和 LaTeX 数学片段能否共用一套追加输入、暂停、预览和结束协议，以及哪些识别规则应由各格式维护。

## 从一次暂停看「自动闭合」

收到 `<div><em>一` 时，界面已经可以把“一”显示在强调节点中。预览可以把当前节点临时视为闭合，解析器仍保留 `em` 的打开状态。下一块若是 `二</em></div>`，两个字应同属一个强调节点。若把临时补出的结束标签写回输入，第二个字就会落在错误的位置。

同一块输入可能停在 `</e`，甚至停在“一”的 UTF-8 字节中间。此时应保留未读完的词或字符，等待下块。只有上游明确发送输入结束（EOF），才应用该格式的结束规则。预览里补出的边界应标为临时；复制原文时只取实际收到的字符。

## 四组能区分方案的样例

| 输入范围 | 分块样例或反例 | 预期观测 |
| --- | --- | --- |
| HTML，先取无属性标签与文本片段 | 分块送入 `<div>一<br>二</div>`，切点落在 `<br` 之后 | 标签名到齐才能识别元素；`br` 是空元素，不期待 `</br>`。再用 `<ul><li>A<li>B</ul>` 检查是否支持省略结束标签，并据此标明 HTML 子集边界。[HTML 解析规范](https://html.spec.whatwg.org/multipage/parsing.html#parsing-main-inbody) |
| Markdown，采用 CommonMark | 先送一行“标题”及换行，再送一行 `---` 及换行 | 上一行从段落预览变为二级标题。树形预览需要能修订已经显示的节点。另测围栏代码块里的 `<div>` 保持字面文本。[Setext 标题](https://spec.commonmark.org/0.31.2/#setext-headings) · [围栏代码块](https://spec.commonmark.org/0.31.2/#fenced-code-blocks) |
| PlantUML，先取时序图 | `@startuml` 内按行送入 `alt 成功`、消息、`else 失败`、消息、`end`、`@enduml` | `else` 切换同一个分组的分支，`end` 结束分组，`@enduml` 结束整图。把消息正文中的单词 `end` 也纳入反例。[PlantUML 时序图分组](https://plantuml.com/sequence-diagram) |
| LaTeX，先取数学模式的分组和分式 | 先送 `\frac{1}`，下一块送 `{2}`，另测原处直接 EOF | 首块的花括号已经配平，命令仍缺分母。继续输入应得到一个分式；原处结束时，严格解析报告缺参，预览可显示带标记的空槽。[LaTeX 内核的分式定义](https://github.com/latex3/latex2e/blob/main/base/ltmath.dtx) |

## 候选方案与验证

第一种方案只配置开始符和结束符，用栈管理嵌套。它适合显式配对的片段，可作为成本最低的对照。第二种方案共用分块输入、原文位置、临时预览和最终结果的交付方式；各格式自行决定怎样分词、怎样更新结构、何时能把节点标为稳定。第三种方案在每次追加后调用现成解析器重算当前全文，作为正确性和开发成本的基线。

首轮对上述短样例逐个遍历每个单切点，并按单字节连续喂入。最终结构、文本范围和诊断应与同一方言的一次性解析一致；每次预览后继续输入，结果也应与从未请求预览时一致。记录每次追加重读的字节数、首次可显示的位置和需替换的节点范围，才有依据判断维护增量状态是否划算。

**待验证的判断**是先统一输入和预览协议，把标签、块、分支和命令参数的语义交给各自解析器。若某类输入还需从外层切入内层（如 Markdown 围栏中标记为 PlantUML 的文本），另测宿主能否把保留原文位置的片段交给图解析器。首轮聚焦只追加的流；任意位置编辑留作单独问题。
